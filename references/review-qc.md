# 审片与 QC

## 铁律：不要逐张读整帧大图

整帧 1920x1080 的 PNG 一张 3MB 上下，一张张读进对话会迅速把请求体撑爆，
撞上服务端 32MiB 的 `413 Payload Too Large` —— 之后那个会话每一轮都会失败。

规矩：

- 看图先出缩略图：`python tools/make-review.py` → `out/contact-sheet.jpg`（全部画面板的总览网格）。
- 一轮最多看 2–3 张图；要比多个镜头就看总览图，不要拉原始大图。
- 视频文件、`bgm.wav`、`.raw/` 原图只确认存在与元数据，不读内容。

## 审片循环

1. `npm run still -- "<幕 id>" out/qc/<名字>.jpg --frame=<关键帧>` 抽几张关键帧。
   挑帧的位置：每幕的开头（章节卡）、字幕最长的那一镜中间、标注动画结束前两帧、转场中段。
2. 把抽出来的帧拼成一张小图再看（`make-review.py` 可以直接吃帧图，输出到 `out/review/`）。
3. 按清单过一遍：
   - 字幕有没有被裁掉、有没有和标注打架？
   - 标注动画（计数、年代戳）有没有在镜头结束前演完？
   - 转场是不是闪一下？两段的运动方向有没有重复？
   - 整片调色是否统一（同一幕里的图看起来像一部片子吗）？
4. 改完再抽同样的帧复看，别凭印象。

## 渲染前后

- 渲染命令一律走 `scripts/run-remotion.mjs`（临时目录被收进工程内 `.tmp`，跑完自动清空）。
- 长片先渲一遍单幕 composition 确认没问题，再渲整片，省得半小时后才发现某一幕崩了。
- 输出文件写在 `out/`。片子大，别把 `out/*.mp4` 读进对话。
